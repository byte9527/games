# 小游戏通用背景音乐与五子棋中国风曲目设计

## 1. 背景

当前项目已提供可安装、可离线运行的小游戏合集，首款游戏为本地双人五子棋。为了让对局过程更有氛围，本次增加低干扰的中国风背景音乐，同时把底层能力设计为可供后续小游戏复用的通用音频模块。

音乐继续遵循项目的核心定位：无广告、无远程运行时依赖、首次加载后可离线使用。五子棋规则核心、对局存档和胜负判断不依赖音频能力；音乐不可用时，游戏仍必须完整可玩。

## 2. 目标

- 五子棋进行期间播放安静的中国风器乐背景音乐。
- 默认开启音乐，但只在浏览器收到首次用户操作并允许播放后开始发声。
- 只提供简洁的音乐开关，使用固定低音量，不增加音量滑块。
- 获胜或和棋时淡出暂停；悔棋恢复对局或重新开始后淡入继续。
- 页面进入后台时暂停，恢复到前台且棋局仍在进行时继续。
- 保存全局音乐偏好，未来其他小游戏共享相同开关状态。
- 建立通用音频架构，后续游戏只需提供自己的曲目配置。
- 音乐相关代码随 PWA 应用资源进入 Cache Storage，保证离线可用。

## 3. 非目标

本次不包含以下能力：

- 音量滑块、均衡器或复杂的声音设置页面。
- 独立的落子、胜利、失败或按钮音效。
- 在线音乐、第三方音乐服务或运行时网络请求。
- 用户上传音乐、选择多首曲目或播放列表。
- 将运行时生成的音频缓冲数据序列化到 Cache Storage。
- 跨设备同步音乐偏好。

## 4. 方案选择

采用 Web Audio API 实时合成音乐，而不是内置音频文件或在线加载音乐。

选择原因：

- 曲目由代码生成，不涉及第三方音乐版权。
- 不增加 `.mp3`、`.ogg` 或 `.wav` 文件带来的安装和离线缓存体积。
- 音乐引擎与曲目配置会打包进应用 JavaScript，现有 Workbox 预缓存机制即可覆盖。
- 可以通过统一配置为后续小游戏生成不同风格的音乐，不需要为每款游戏重新实现播放生命周期。

不采用外部音乐资源，因为它会破坏离线能力，并引入网络、隐私和版权风险。

## 5. 通用音频架构

音频能力放在 `src/audio/`，不放入五子棋内部。建议边界如下：

```text
src/
  audio/
    core/                 # 通用音频端口、调度器、音符与曲目类型
    storage/              # 全局音乐偏好存储
    AudioProvider.tsx     # 应用级音频服务与 AudioContext 生命周期
    MusicToggle.tsx       # 可复用的音乐开关
    useGameMusic.ts       # 游戏页面接入 Hook
  games/
    gomoku/
      audio/
        gomokuMusicScore.ts # 五子棋中国风曲目配置
      GomokuPage.tsx
```

### 5.1 `AudioProvider`

`AudioProvider` 在应用级提供单例音频服务，职责包括：

- 延迟创建和解锁 `AudioContext`。
- 维护全局音乐开关及其持久化状态。
- 接收当前游戏的曲目和活动状态。
- 统一处理开始、淡入、淡出、暂停、恢复和停止。
- 监听页面可见性变化，避免应用在后台继续播放。
- 游戏切换或应用卸载时取消调度并释放资源。
- 将可预期的浏览器或存储失败转换为明确的服务状态。

同一时间只允许一个游戏曲目处于活动状态，避免后续小游戏之间出现多个音频上下文或音乐重叠。

### 5.2 `useGameMusic`

游戏页面通过 `useGameMusic` 声明音乐需求，输入至少包含：

- 当前曲目 `MusicScore`。
- 当前是否处于需要播放音乐的活动状态。

五子棋把 `game.status === 'playing'` 作为活动状态。Hook 只负责注册和更新音乐场景，不直接访问棋盘、落子历史或胜负规则。

### 5.3 `MusicScore`

`MusicScore` 是通用曲目描述，包含：

- 稳定的曲目标识。
- 速度、拍号与循环长度。
- 音阶和音符序列。
- 各声部的音色类型、音域、包络和相对音量。
- 总体目标音量和淡入淡出时间。

通用引擎解释曲目描述并调度 Web Audio 节点。游戏模块不能直接操作 `AudioContext`，从而保证后续曲目复用同一套生命周期和异常处理。

### 5.4 `MusicToggle`

`MusicToggle` 是共享按钮组件，展示“音乐开”或“音乐关”，并暴露明确的可访问名称和按下状态。音频不可用时按钮禁用，并关联不可用原因提示。

## 6. 五子棋曲目设计

五子棋曲目采用安静的中国风器乐方向：

- 使用中国五声音阶组织旋律。
- 速度约为 60 BPM，循环长度约 32 秒。
- 主声部为短促、衰减自然的拨弦音色，模拟克制的古琴氛围。
- 辅助声部为低音量持续音和少量笛音式长音。
- 节奏留白较多，避免持续密集的旋律干扰思考。
- 总音量保持在明显低于一般媒体播放的水平。
- 循环首尾共享稳定的和声落点，避免明显跳变。

曲目由确定性配置生成，不在每次进入时随机改变核心旋律，保证测试稳定且用户体验一致。用于减少机械感的细微音量和起音变化预先写入曲目配置，不使用运行时随机数。

## 7. 交互与播放生命周期

### 7.1 进入页面

1. `AudioProvider` 读取全局音乐偏好，首次默认为开启。
2. 五子棋注册曲目，并声明当前棋局是否正在进行。
3. 在浏览器尚未允许播放时，界面显示“音乐开”，但不强行创建或启动音频。
4. 用户第一次落子、点击音乐按钮或执行键盘操作后，音频服务创建并恢复 `AudioContext`。
5. 如果音乐开启、页面可见且棋局正在进行，曲目淡入播放。

### 7.2 音乐开关

- 用户关闭音乐时立即开始短暂淡出，完成后停止曲目调度。
- 用户重新开启音乐时，这次点击本身作为用户操作解锁音频，并在棋局进行中淡入播放。
- 开关状态写入全局偏好，进入其他小游戏时沿用。
- 如果偏好写入失败，本次页面内状态仍然有效，但明确提示无法跨刷新保存。

### 7.3 棋局状态变化

- `playing → won/draw`：音乐淡出并暂停。
- `won/draw → playing`：例如结果弹窗中悔棋，音乐淡入恢复。
- 重新开始：新棋局处于 `playing`，音乐保持或恢复播放，不重新创建音频上下文。
- 离开五子棋页面：注销当前曲目并停止调度。

### 7.4 页面可见性

- 页面隐藏或应用进入后台时暂停音乐和未来音符调度。
- 页面重新可见时，只有在音乐开启、当前游戏仍注册且棋局正在进行时才恢复。
- 后台暂停不改变用户的音乐开关偏好。

## 8. 浏览器自动播放限制

现代浏览器通常禁止页面在没有用户操作时自动播放音频。本设计不通过静默失败或循环重试绕过限制，而是把“用户尚未解锁音频”作为明确状态。

- `AudioContext` 只在首次可信用户操作后创建或恢复。
- 默认开启表示“具备播放条件后自动开始”，不表示页面加载瞬间强制发声。
- 如果恢复操作被浏览器拒绝，音乐服务保持可重试状态；用户再次点击音乐按钮时可以重试。
- 不因自动播放限制显示错误，只有确认浏览器不支持或音频上下文创建失败时才标记为不可用。

## 9. 偏好存储

- 使用带应用命名空间和版本号的 `localStorage` 键保存全局音乐开关。
- 存储值采用严格结构校验，不使用宽松字符串判断拼凑状态。
- 缺少记录时默认开启。
- 无效记录回退到默认开启，并用新格式覆盖前先等待下一次用户主动修改。
- 读取或写入不可用时，音乐功能继续使用当前内存状态，同时显示一次非阻塞提示。

该回退是业务正确性的一部分：偏好持久化不是运行音乐或进行棋局的前提，但失败不能被静默隐藏。

## 10. PWA 与 Cache Storage 策略

当前曲目没有独立音频文件。音乐引擎与 `gomokuMusicScore` 会进入构建后的 JavaScript 文件，并由现有 Workbox 规则预缓存到 Cache Storage，因此首次成功加载后可以离线初始化和播放。

不把运行时生成的 `AudioBuffer` 写入 Cache Storage，原因包括：

- 相同数据可由已缓存的代码即时重建。
- Cache Storage 面向请求和响应，不适合作为音频运行时对象存储。
- 序列化会增加格式版本、缓存迁移和清理复杂度，却不会减少网络请求。

为未来真实音频文件预留规则：如果后续游戏引入本地 `.mp3`、`.ogg` 或 `.wav`，必须把对应扩展名加入 Workbox 预缓存范围，并验证部署在 `/games/` 基础路径时仍能正确缓存和离线读取。

## 11. 异常处理

音频异常不得影响棋局核心：

- Web Audio API 不可用或上下文创建失败：音乐按钮禁用，并提示“当前浏览器无法播放音乐”。
- 音频恢复暂时被浏览器拒绝：保留可重试状态，不标记为永久不可用。
- 曲目配置无效：在开发和测试中明确失败；生产环境停止该曲目并显示不可用提示，不启动不完整调度。
- 偏好读取或写入失败：使用当前页面内状态，并提示无法保存音乐设置。
- 页面切换、组件卸载或 StrictMode 重放：调度器必须幂等清理，不能残留定时器、节点或重复曲目。

只有已识别、可恢复的浏览器能力和存储问题由音频模块转换为状态。未知编程错误继续交给应用错误边界处理，不能使用宽泛 `catch` 吞掉。

## 12. 测试设计

### 12.1 音乐引擎单元测试

- 正确解释速度、音阶、声部和循环长度。
- 调度的音符时间单调递增且位于预期循环内。
- 固定总音量不超过设计上限。
- 开始、淡入、淡出、暂停、恢复和停止调用正确。
- 停止和释放为幂等操作，不残留调度任务。
- 无效曲目配置产生明确失败结果。

测试使用可注入的音频端口和可控时钟，不依赖真实扬声器或真实时间等待。

### 12.2 `AudioProvider` 与偏好测试

- 首次默认开启，但用户操作前不创建音频上下文。
- 首次点击或键盘操作后解锁，并只创建一个上下文。
- 关闭和重新开启音乐正确更新播放状态与持久化值。
- 页面隐藏时暂停，重新可见时按条件恢复。
- 切换游戏曲目时旧曲目停止，新曲目启动且不重叠。
- Web Audio API 不可用、创建失败和恢复被拒绝时状态正确。
- 偏好数据缺失、无效、读取失败和写入失败均按设计处理。
- StrictMode effect 重放后仍只有一个活动音乐服务。

### 12.3 组件与五子棋集成测试

- 音乐按钮展示正确名称、按下状态、禁用状态和提示关联。
- 点击音乐按钮可以开关音乐，键盘可以完成同样操作。
- 棋局进行时声明音乐活动，获胜或和棋时声明暂停。
- 终局悔棋和重新开始后恢复音乐活动。
- 音频失败不会改变棋盘、回合、历史或存档。

### 12.4 E2E 与离线验证

- 关闭音乐后刷新页面仍保持关闭，再次开启后保持开启。
- 从五子棋返回合集页面后，音乐调度停止且页面无控制台错误。
- 页面进入后台和恢复前台时，音乐状态符合约定。
- 首次联网加载后，断网重载仍可进入五子棋并初始化音乐模块。
- 离线运行期间不产生第三方或远程音乐请求。
- 默认构建和 `/games/` 部署构建均包含正确的音乐代码与缓存清单。

E2E 不通过麦克风或扬声器判断是否真实发声。播放时序和节点调用由可控音频端口的单元测试负责，E2E 验证用户可见状态、持久化、生命周期和运行时错误。

## 13. 完成标准

满足以下条件时，本功能可视为完成：

- 五子棋进行中可播放低音量中国风循环音乐。
- 音乐默认开启，并遵守浏览器首次用户操作限制。
- 用户可以通过单一按钮开关音乐，偏好在刷新和其他小游戏间共享。
- 终局、悔棋、重开、后台、前台和页面切换行为符合设计。
- 音乐不可用或偏好存储失败时有明确提示，棋局仍完整可用。
- 通用音频模块不依赖五子棋规则，其他小游戏可通过 `MusicScore` 和 `useGameMusic` 接入。
- 离线环境不请求外部音乐资源，音乐代码已进入 Cache Storage。
- 单元测试、组件测试、类型检查、构建和相关 E2E 全部通过。
- 默认路径和 GitHub Pages `/games/` 路径均验证通过。

## 14. 已知风险与控制

- **浏览器自动播放限制差异**：不同浏览器解锁条件不同。通过只在可信用户操作后创建或恢复上下文，并保留可重试状态控制风险。
- **实时调度漂移**：后台计时器可能被浏览器节流。通过页面隐藏时暂停、恢复时重新建立调度窗口控制风险。
- **合成音色过于机械**：通过短包络、留白、多声部和克制的微小变化改善，但保持确定性以便测试。
- **移动设备耗电**：控制同时存在的节点数量、提前调度窗口和总声部数，页面后台或游戏结束后停止调度。
- **共享模块过度设计**：首版只抽象已经由五子棋实际使用的上下文生命周期、偏好、曲目和开关，不提前加入播放列表、音效总线或复杂混音功能。
