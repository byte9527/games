# 数独游戏设计

## 1. 背景

当前项目是一个无广告、无账号、无用户追踪、支持离线使用的 PWA 小游戏合集，已包含本地双人五子棋。第二款游戏选择标准 9×9 数独，补充适合手机单人游玩的益智类型，并继续复用现有路由、存储、音乐、可访问性、响应式布局和离线基础设施。

首版使用内置精选题库，不在浏览器运行时生成题目。这样可以稳定保证每道题有唯一解、难度标注可靠、首次打开即可游玩，并避免移动设备在生成和评估题目时产生明显等待。题目访问通过通用提供器接口隔离，未来可以增加更多题包或本地生成器，而不改变棋局状态和页面组件。

## 2. 目标

- 提供标准 9×9 单人数独。
- 提供简单、中等、困难三个难度。
- 完全离线运行，不请求远程题目、音频、字体、统计或其他运行时资源。
- 自动保存并恢复当前未完成棋局。
- 支持候选数、擦除、撤销、重新开始和更换题目。
- 在手机触控、桌面鼠标和键盘环境下都能完整游玩。
- 复用现有全局音乐偏好和浏览器音频生命周期。
- 保持数独规则、题库、存储和界面之间边界清晰，方便未来增加其他益智游戏。

## 3. 非目标

首版不实现以下能力：

- 在线账号、云同步或排行榜。
- 每日挑战、连续签到或奖励系统。
- 人机对战、本地双人或在线对战。
- 提示答案、自动解题或逐步教学。
- 倒计时、生命值、失败次数限制或广告式复活。
- 运行时随机生成数独题目。
- 历史完成记录、跨设备最佳成绩或分享结果图片。
- 4×4、6×6、16×16 等其他棋盘规格。

## 4. 核心规则

- 棋盘固定为 9 行、9 列，并划分为九个 3×3 宫。
- 每一行、每一列和每一个 3×3 宫都必须包含 1 至 9，且不能重复。
- 题目给定数字不可修改、擦除或添加候选数。
- 普通输入模式下，数字键会把选中空格设置为对应数字。
- 候选模式下，数字键会切换选中空格中的对应候选数。
- 擦除会清空玩家填写的数字或当前格全部候选数，不影响给定数字。
- 玩家填写正式数字后，当前格候选数被清空；同行、同列和同宫其他空格中的相同候选数自动移除。
- 撤销必须恢复一次操作造成的全部变化，包括正式数字、当前格候选数和被自动移除的关联候选数。
- 填写造成同行、同列或同宫重复时，相关玩家输入格进入冲突状态；不直接依据标准答案标记一个尚未形成冲突的错误数字。
- 棋盘填满并满足全部数独约束时判定完成。内置题目具有唯一解，因此完整合法棋盘必然是该题答案。

## 5. 题库与难度

### 5.1 内置题库

首版至少包含 60 道题：简单、中等、困难各 20 道。题目数据随应用 JavaScript 一同构建并由 Service Worker 预缓存，不产生运行时网络请求。

每道题包含：

- 全局唯一且稳定的题目标识。
- 难度等级。
- 81 位初始棋盘字符串，`0` 表示空格。
- 81 位标准答案字符串。

构建测试必须验证：

- 初始棋盘和答案格式正确。
- 给定数字与答案一致。
- 答案满足全部行、列、宫约束。
- 初始棋盘恰好存在一个解。
- 同一难度内题目标识不重复。

### 5.2 题目选择

- 首次进入默认选择简单难度。
- 如果存在有效的未完成存档，优先恢复存档，不重新抽题。
- 更换题目时从当前难度题库中选择与上一题不同的题目。
- 难度切换会开始该难度的新题；已有进度时必须先确认。
- 题目选择逻辑封装为提供器接口。首版提供内置题库实现，未来生成器或扩展题包使用同一接口。

## 6. 用户流程

### 6.1 进入游戏

1. 用户从小游戏合集进入数独页面。
2. 页面读取当前活动存档。
3. 有有效存档时恢复题目、玩家输入、候选数、撤销历史、难度和已用时间。
4. 没有存档时创建一局简单难度的新题。
5. 存档损坏或版本不支持时显示明确提示，并允许开始新游戏，不静默伪装为成功恢复。
6. 存储不可访问时显示“本次进度无法保存”提示，但棋局仍可完整进行。

### 6.2 游玩

- 点击或触摸格子选择当前位置。
- 选中格后突出显示同行、同列、同宫，以及棋盘上相同的正式数字。
- 手机端使用页面数字键盘输入；桌面端也可直接使用键盘。
- 候选模式有明确的开启状态，不因输入一个候选数自动退出。
- 无可撤销操作时撤销按钮禁用。
- 当前输入造成冲突时显示视觉状态，并通过可访问状态区域说明存在冲突。

### 6.3 重新开始、换题与切换难度

- “重新开始”恢复当前题目的初始状态，清除玩家输入、候选数、历史和计时，需要确认。
- “换一题”在当前难度选择另一道题，需要确认已有进度。
- 切换难度会创建新题，需要确认已有进度。
- 空白新局尚未产生玩家操作时，可以直接换题或切换难度，不显示多余确认。

### 6.4 完成

- 完成后停止计时和背景音乐，并显示完成弹窗。
- 弹窗展示难度和本局用时。
- 用户可以选择“再来一题”或“返回小游戏”。
- 已完成棋局不作为活动棋局恢复，也不保存历史成绩。

## 7. 输入与键盘操作

### 7.1 手机与指针输入

- 棋盘格最小触控目标遵循移动端可用尺寸，数字键盘按钮保持足够间距。
- 数字键盘包含 1 至 9、候选模式和擦除。
- 页面控制区包含难度、撤销、重新开始和换一题。
- 选中给定格时仍允许查看关联高亮，但数字键盘不能修改该格。

### 7.2 键盘输入

- 方向键在棋盘内移动焦点和选中格。
- `1` 至 `9` 输入正式数字或切换候选数。
- `Delete` 和 `Backspace` 擦除玩家输入。
- `N` 切换候选模式。
- `Ctrl+Z` 和 `Meta+Z` 撤销一步。
- `Home` 移动到当前行第一列，`End` 移动到当前行最后一列。
- 焦点始终保持可见；打开确认弹窗或完成弹窗时，背景内容进入 `inert` 状态，关闭后恢复到触发控件。

## 8. 状态模型与操作历史

棋局状态至少包含：

- `puzzleId` 和难度。
- 固定给定数字。
- 当前 81 格正式数字。
- 每格候选数位集。
- 当前选中格。
- 候选模式开关。
- 操作历史栈。
- 已累计用时。
- `playing` 或 `completed` 状态。

核心规则层使用不可变状态转换。页面和 React Hook 不直接实现行、列、宫计算。

一次历史记录保存该次操作产生的格子差异集合，而不是只保存被点击格。这样在输入正式数字自动清理关联候选数后，撤销可以原子恢复全部变化。选择格子、切换候选模式和纯界面焦点变化不进入撤销历史。

## 9. 计时

- 计时从新题创建或有效存档恢复后开始。
- 计时只在棋局为 `playing` 且页面可见时累计。
- 页面隐藏、打开系统切换界面或棋局完成时暂停累计。
- 页面恢复可见后继续累计，不把后台停留时间计入成绩。
- 显示层每秒刷新一次，但持久化以累计毫秒为准，避免刷新间隔漂移影响真实用时。
- 计时器、可见性监听和刷新任务在页面卸载及 StrictMode effect 重放时必须完整清理。

## 10. 本地存储

数独使用独立、带版本的存储键，不复用五子棋 schema。存储层与游戏规则层通过端口隔离。

活动存档至少包含：

- schema 版本。
- 题目标识和难度。
- 当前正式数字与候选数。
- 可序列化的操作历史。
- 已累计用时。
- 最近保存时间。

另外保存每个难度最近使用的题目标识，用于避免连续出现同一题。该记录不包含完成历史或用户身份。

保存时机：

- 正式数字、候选数、撤销、重新开始或换题后。
- 页面进入隐藏状态时。
- 页面卸载前的同步浏览器存储边界。

错误处理：

- JSON 损坏、字段缺失、未知字段、非法数字、无效题目标识或历史不一致均判定为损坏存档。
- 损坏存档显示提示并从新题开始，不把损坏数据写回为正常存档。
- `localStorage` 读取或写入失败映射为明确的不可用状态。
- 存储失败只影响恢复和持久化，不得阻断数独输入、校验或完成流程。

## 11. 音乐与音效

- 数独复用应用级 `AudioProvider`、`useGameMusic`、`MusicToggle` 和全局音乐偏好。
- 新增一首数独专属低音量背景曲目，整体方向为舒缓、留白较多的轻柔拨弦与持续音。
- 曲目通过 Web Audio API 本地合成，不包含远程或本地媒体文件。
- 音量上限不高于五子棋曲目的现有安全范围。
- 只有棋局为 `playing` 时注册为活动音乐场景；完成、离开页面或关闭音乐时按现有生命周期淡出和清理。
- 页面隐藏与恢复、首次可信激活、浏览器挂起恢复和全局开关完全复用现有音频架构，不为数独增加平行音频状态机。
- 首版不增加按键音、错误音或完成音效，避免与背景音乐开关语义和无障碍反馈重复。

## 12. 页面与组件

建议目录：

```text
src/games/sudoku/
├── audio/
├── components/
├── core/
├── puzzles/
├── storage/
├── SudokuPage.tsx
├── sudoku.css
└── useSudokuGame.ts
```

组件职责：

- `SudokuPage`：组合页面、存储状态、音乐场景和弹窗，不实现数独规则。
- `SudokuBoard`：渲染 81 格、焦点移动、选中与可访问描述。
- `NumberPad`：数字、候选模式和擦除，不持有棋局状态。
- `SudokuControls`：难度、撤销、重新开始、换题和返回入口。
- `CompletionDialog`：完成结果和下一步操作。
- `ConfirmDialog`：保护重新开始、换题和切换难度操作。
- `NoticeBanner`：存档损坏、存储不可用和冲突状态提示。

规则模块职责：

- 坐标和 3×3 宫计算。
- 冲突集合计算。
- 候选数位集读写。
- 正式数字与候选输入的不可变状态转换。
- 撤销差异生成和恢复。
- 完成校验。

题库模块职责：

- 题目数据模型。
- 题目格式和唯一解验证。
- 按难度选择下一题。
- 通过接口向 Hook 提供题目，不访问 React 或本地存储。

## 13. 响应式与视觉状态

- 页面优先适配 320px 至 430px 手机竖屏，不产生水平滚动。
- 棋盘保持正方形，最大宽度受页面内容宽度限制。
- 3×3 宫边界比普通格线更明显，但不能只依靠颜色区分。
- 给定数字、玩家数字、候选数、选中格、关联区域、相同数字和冲突状态具有不同且可辨识的视觉层级。
- 深色文字和背景满足可读性，支持强制颜色模式。
- `prefers-reduced-motion` 下关闭非必要过渡和完成动画。
- 桌面宽屏可以将棋盘和控制区并排；手机保持棋盘、数字键盘、控制区的单列顺序。

## 14. 可访问性

- 棋盘使用明确的分组语义和 81 个可聚焦格子。
- 每格可访问名称包含行、列、给定或玩家数字、候选数和冲突状态。
- 当前选中格和焦点格分别表达，不能只依赖颜色。
- 候选模式开关使用稳定名称和 `aria-pressed`。
- 冲突、存储问题和完成结果通过状态区域或对话框表达。
- 禁用按钮提供可理解原因，例如“暂无可撤销操作”。
- 弹窗具有焦点圈定、Escape 取消、背景隔离和关闭后焦点恢复。
- 数字键盘的视觉状态文字不改变按钮稳定的可访问名称。

## 15. 离线与隐私

- 数独代码、题库、样式和本地合成音乐配置进入现有 PWA 构建和预缓存。
- 离线重载后可以恢复活动棋局、输入数字、使用候选数、撤销和开始新题。
- 浏览器测试必须从首次导航前监听全部 HTTP(S) 请求，拒绝任何跨域请求，并单独拒绝所有媒体请求。
- 不收集题目完成时间、输入过程或设备信息。
- 所有数独状态只保存在当前浏览器，清除站点数据后不可恢复。

## 16. 错误处理

- 规则层对非法坐标、非法数字、无效位集和不一致题目抛出明确错误，不静默修正。
- 页面只把可预期的存储损坏或不可用转换为用户可理解状态。
- 题库格式或唯一解验证失败属于开发错误，由测试和错误边界暴露，不能在生产环境随机换题掩盖。
- 音频不可用只影响音乐，并显示现有全局提示；数独输入和完成流程继续可用。
- 确认操作取消后不得修改棋局、计时、历史或存档。

## 17. 测试策略

### 17.1 单元测试

- 行、列、宫坐标和关联格集合。
- 冲突检测和完成校验。
- 候选数切换、自动清理和撤销恢复。
- 给定数字不可修改。
- 历史差异的原子性和输入不可变。
- 题库格式、答案合法性和唯一解。
- 难度选择不连续重复。
- 存储 schema、损坏数据、不可用存储和版本拒绝。
- 计时在隐藏、恢复、完成和卸载时的生命周期。
- Hook 的重新开始、换题、难度切换、存档恢复与完成流程。
- 数独音乐曲目格式与音量上限。

### 17.2 组件测试

- 触控数字键盘、候选模式、擦除和撤销。
- 键盘方向、数字、Delete、Backspace、N 和撤销快捷键。
- 选中、相同数字、关联区域和冲突的语义与样式状态。
- 确认弹窗和完成弹窗的焦点、背景隔离与恢复。
- 存储或音频不可用时棋局仍可完整操作。
- StrictMode 下监听器和定时器不重复、不残留。

### 17.3 浏览器测试

- 从合集进入数独，完成一次输入、候选、撤销和刷新恢复流程。
- 切换难度、重新开始和换题确认流程。
- 桌面键盘完整操作。
- 320px 手机视口无横向溢出，数字键盘和棋盘可触控。
- 页面隐藏与恢复后计时和音乐状态正确。
- 离线重载后恢复棋局并继续输入。
- 无页面错误、控制台错误、跨域请求或媒体请求。
- GitHub Pages `/games/` 基础路径和 Service Worker 预缓存包含数独代码与题库。

## 18. 验收标准

- 用户首次进入即可在简单难度开始一局合法且唯一解的 9×9 数独。
- 简单、中等、困难各至少 20 道题，且不会连续选择同一道题。
- 普通数字、候选数、擦除、撤销、重新开始、换题和难度切换行为符合设计。
- 冲突即时可见，但不会直接泄露尚未形成冲突的错误答案。
- 刷新和离线重载可以恢复未完成棋局及用时。
- 页面隐藏期间不累计时间、不播放音乐；恢复后生命周期正确。
- 完成后停止计时和音乐，活动存档不再恢复。
- 音频或存储失败不影响完成整局数独。
- 320px 手机视口、桌面键盘、强制颜色和减少动画模式可用。
- 不产生跨域请求、媒体请求、广告、统计或用户追踪。
- 全量单元测试、类型检查、生产构建、Pages 基础路径检查和 Chromium E2E 通过，Critical 和 Important 评审问题为 0。

## 19. 后续扩展

以下能力仅作为架构预留，不属于首版实施范围：

- 浏览器本地题目生成器和难度分析器。
- 更多内置题包。
- 提示、解题步骤和教学模式。
- 每日挑战、本地完成记录和最佳用时。
- 其他棋盘规格或数独变体。

题目提供器、规则核心和存储 schema 必须保持独立，使这些扩展可以逐项增加，而不修改现有页面对基础数独棋局的依赖方式。
