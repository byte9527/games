# 数独手机端紧凑布局设计

## 背景

当前数独页面在手机竖屏中纵向占用较长。棋盘下方的数字键盘使用三列布局，11 个按钮需要四行；再叠加控制区、难度选择、标题、元信息和冲突提示后，正常棋局在常见手机视口中需要页面滚动才能操作底部按钮。

本次优化只调整手机端布局，不改变数独规则、状态、存档、音频或组件交互语义。

## 目标

- 无通知、无弹窗的正常棋局在 320×740 及以上常见竖屏中无需页面滚动。
- 棋盘保持当前可用最大宽度，不通过缩小棋盘换取纵向空间。
- 所有独立操作按钮保持至少 44×44px 的触控目标。
- 数字、候选、撤销、重新开始、换题和难度选择仍直接可见，不引入折叠菜单。
- 768px 及以上现有桌面双栏布局保持不变。

## 非目标

- 不调整棋局规则、题库、存档格式、计时或音乐。
- 不改变组件公开 API、DOM 顺序或可访问名称。
- 不要求通知横幅、PWA 安装提示或更新提示出现时仍完全无滚动；这些是需要完整展示的临时状态。
- 不把 9×9 棋盘格提升到 44×44px。棋盘格继续使用既有紧密网格例外，独立控制按钮仍满足 44×44px。

## 布局方案

采用“移动端双行数字键盘”方案，仅在视口宽度小于 760px 时生效。

### 标题与状态区

- 保留返回链接、标题和音乐开关的同一行结构。
- 缩小移动端标题区内部间距和标题下方留白，不降低返回链接或音乐开关的触控高度。
- 难度、用时和冲突提示继续完整显示，但减少胶囊内边距及区块间距。

### 棋盘

- 保持宽度为当前内容区可用宽度，继续使用 `aspect-ratio: 1`。
- 不缩小玩家数字、给定数字或候选数字。
- 宫线、焦点、选中、关联、同值和冲突样式保持不变。

### 数字键盘

- 将 `.number-pad` 在移动端改为六列布局。
- 第一行依次显示数字 1–6。
- 第二行依次显示数字 7–9、候选模式和擦除。
- 候选模式按钮占两列，使 9 个数字、候选模式和擦除恰好组成两行。
- 移动端列间距使用 4px；在 320px 视口和现有页面边距下，每个单列按钮宽度约 46px。
- 按钮 DOM 顺序、键盘操作和可访问名称保持不变。

### 其他控制区

- 撤销、重新开始和换题保持三列一行。
- 简单、中等和困难保持三列一行。
- 收紧数字键盘、控制区和难度选择之间的垂直间距。
- 不合并按钮，不隐藏次要操作，不新增“更多”菜单。

## 响应式边界

- `<760px`：启用紧凑单列布局和六列数字键盘。
- `>=760px`：继续使用现有棋盘与控制面板双栏布局，不继承移动端的六列数字键盘。
- `<=380px`：保留现有较细棋盘外框和宫线规则，同时满足 320px 无水平溢出。

## 可访问性

- 独立按钮宽高均不得小于 44px。
- 棋盘格维持现有紧密网格例外，但必须保持可聚焦、可点击和键盘可操作。
- 不改变 `role`、`aria-label`、`aria-pressed`、禁用状态或焦点恢复语义。
- 强制颜色和减少动画规则继续生效。

## 测试策略

按 TDD 实施：先加入真实浏览器失败测试，再修改样式。

### 浏览器测试

- 320×740 和 375×812：无通知、无弹窗的正常棋局满足 `scrollHeight <= innerHeight`，同时无水平溢出。
- 数字键盘 11 个按钮形成两行：1–6 同行，7–9、候选模式和擦除同行。
- 候选模式按钮宽度约等于两个普通数字按钮加一个列间距。
- 数字键盘、撤销、重新开始、换题和三个难度按钮均至少 44×44px。
- 768px 及桌面视口继续保持既有双栏结构。
- 原有键盘、强制颜色、减少动画、弹窗隔离和焦点恢复测试继续通过。

### 代码级测试

- 仅在现有 CSS 契约测试有必要时补充移动端 media query 和六列布局约束。
- 不以源码正则代替真实首屏高度和按钮几何尺寸验证。

## 验收标准

- 正常数独棋局在 320×740、375×812 竖屏无需页面滚动。
- 数字键盘为两行且所有功能直接可见。
- 棋盘未缩小，独立按钮保持 44×44px。
- 768px 及桌面布局无回归。
- 单元测试、类型检查、构建和双 Chromium E2E 全部通过。
- 工作树干净，提交已推送至 `origin/main`。
